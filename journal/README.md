# Journal

A running record of the user's working life, kept while it happens rather than
reconstructed from memory at the next job search. It's deliberately loose:
dated entries, raw notes, no fixed format. By default, one file per month
(`2027-03.md`), but change that if something else suits the user better.

The most valuable things to capture:

- **Impact:** what changed because of the user's work, with numbers whenever
  there are any.
- **Stories:** problems solved and how, decisions made, things that went
  sideways.
- **Recognition:** praise, feedback, reviews.
- **Tools and skills:** what the user used or learned, and how deeply.
- **The bad parts:** mistakes, friction, what made a team or role a poor fit.
  They're lessons, and they help the user judge their next role.

The journal stays raw. Durable facts get promoted into the biography and
lessons into the playbook as they become clear, and the entry stays as it was.

Note which details are internal to an employer, so they never reach anything
public.

This part of the workspace has the least experience behind it. Start minimal,
and let the user and future sessions work out what makes it useful.
